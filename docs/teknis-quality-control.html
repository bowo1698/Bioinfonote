Catatan. Tutorial ini memakai Bash di Linux dan data publik nyata GSE94345 yang telah diunduh secara lokal. Jalankan perintah dari akar repositori Bioinfonote. FASTQ dan seluruh hasil berada pada docs/data/rnaseq-gse94345/, direktori yang sengaja tidak dilacak Git.

Tujuan dan data contoh

Quality control (QC) adalah pemeriksaan terhadap FASTQ sebelum alignment atau kuantifikasi. Tujuannya untuk menemukan masalah teknis yang dapat mempengaruhi data biologis atau menurunkan kualitas analisis berikutnya.

Tutorial ini akan memakai enam pasangan paired-end reads RNA-seq ragi (Saccharomyces cerevisiae) dari GEO GSE94345: tiga replikasi tanpa doxycycline dan tiga replikasi dengan doxycycline. Studi ini meneliti respons transkripsi ketika domain aktif SPT23p90 diinduksi doxycycline.

Unduh FASTQ melalui SRA

Enam run SRA pada studi ini menghasilkan dua belas FASTQ, masing-masing R1 dan R2. Total berkas FASTQ terkompresi sekitar 623 MiB. Selama proses berlangsung, sediakan ruang kosong sekitar 8-10 GiB untuk berkas SRA, FASTQ sementara, referensi, dan hasil analisis berikutnya. Semua berkas akan disimpan di docs/data/rnaseq-gse94345/.

Menggunakan anacona, kita akan menginstall beberapa tools, seperti sra-tools, fastqc, dan multiqc di lingkungan conda rnaseq, serta juga menginstall cutadapt langsung dengan pip:

# bash
conda create -n rnaseq -y
conda activate rnaseq
conda install -c bioconda -c conda-forge sra-tools fastqc multiqc -y
python -m pip install cutadapt

Berikutnya, unduh data dengan SRA Toolkit. prefetch menyimpan arsip SRA terlebih dahulu. Sesudah itu fasterq-dump mengubah tiap arsip menjadi dua FASTQ. Bila unduhan terputus, jalankan kembali baris prefetch yang sama; toolkit melanjutkan run yang belum lengkap.

# bash
set -euo pipefail

ROOT="$(pwd)"
DD="$ROOT/docs/data/rnaseq-gse94345"
mkdir -p "$DD/sra" "$DD/raw_reads" "$DD/_tmp"

# unduh enam run SRA
prefetch --progress --output-directory "$DD/sra" \
  SRR5220163 SRR5220164 SRR5220165 SRR5220166 SRR5220167 SRR5220168

# ubah setiap run menjadi satu pasangan FASTQ dan beri nama sampel yang jelas
runs=(SRR5220163 SRR5220164 SRR5220165 SRR5220166 SRR5220167 SRR5220168)
samples=(spt23p90_untreated_1 spt23p90_untreated_2 spt23p90_untreated_3 \
  spt23p90_dox_1 spt23p90_dox_2 spt23p90_dox_3)

for i in "${!runs[@]}"; do
  fasterq-dump --split-files --threads 4 --temp "$DD/_tmp" \
    --outdir "$DD/raw_reads" "$DD/sra/${runs[$i]}/${runs[$i]}.sra"
  mv "$DD/raw_reads/${runs[$i]}_1.fastq" "$DD/raw_reads/${samples[$i]}_R1.fastq"
  mv "$DD/raw_reads/${runs[$i]}_2.fastq" "$DD/raw_reads/${samples[$i]}_R2.fastq"
done
gzip "$DD"/raw_reads/*.fastq

Setelah konversi selesai, struktur foldernya seperti ini.

docs/data/rnaseq-gse94345/
└── raw_reads/                 # 12 FASTQ, enam pasangan read penuh

Folder sra/ dan _tmp/ hanya diperlukan saat unduhan serta konversi. Setelah FASTQ selesai dibuat dan Anda sudah memeriksanya, keduanya boleh dihapus untuk menghemat ruang.

Memahami FASTQ

Satu read FASTQ selalu terdiri dari empat baris: header, sekuens basa, tanda +, dan karakter kualitas Phred. R1 dan R2 adalah pembacaan dari dua arah fragmen biologis yang sama; keduanya harus diproses sebagai satu pasangan.

# bash
DD="$(pwd)/docs/data/rnaseq-gse94345"

# tampilkan dua read pertama dari R1
gunzip -c "$DD/raw_reads/spt23p90_untreated_1_R1.fastq.gz" | head -8

# jumlah read dalam sebuah berkas FASTQ: empat baris untuk satu read
gunzip -c "$DD/raw_reads/spt23p90_untreated_1_R1.fastq.gz" | awk 'END {print NR / 4}'

Jangan mengedit FASTQ mentah. Semua hasil QC dan trimming ditulis di bawah $DD/_pipe/, sehingga raw_reads/ tetap dapat menjadi sumber yang dapat diaudit ulang.

Menjalankan FastQC dan MultiQC

FastQC memeriksa setiap FASTQ; MultiQC menggabungkan semua hasil ke satu laporan. Perintah berikut memakai enam nama sampel yang baru saja dibuat pada tahap unduhan, sehingga hanya dua belas FASTQ utama yang diproses.

# bash
DD="$(pwd)/docs/data/rnaseq-gse94345"
samples=(spt23p90_untreated_1 spt23p90_untreated_2 spt23p90_untreated_3 \
  spt23p90_dox_1 spt23p90_dox_2 spt23p90_dox_3)
mkdir -p "$DD/_pipe/qc" "$DD/_pipe/multiqc"

for s in "${samples[@]}"; do
  fastqc --threads 4 --outdir "$DD/_pipe/qc" \
    "$DD/raw_reads/${s}_R1.fastq.gz" \
    "$DD/raw_reads/${s}_R2.fastq.gz"
done

multiqc --force --outdir "$DD/_pipe/multiqc" "$DD/_pipe/qc"

Buka docs/data/rnaseq-gse94345/_pipe/multiqc/multiqc_report.html pada browser anda. Laporan itu adalah hasil QC awal untuk tutorial ini.

Gambar di atas memberi gambaran cepat tentang dua belas file FASTQ, yang meliputi kedalaman read, proporsi GC, dan tingkat duplikasi. Angka ini bukan alasan untuk langsung memangkas read. Kita perlu melihat panel atau parameter FastQC lainnya sebelum melakukan tindakan tertentu seperti trimming.

Membaca hasil dan memutuskan perlu tidaknya trimming

Kriteria berikut membantu membedakan masalah yang memang perlu tindakan dari pola yang wajar pada RNA-seq.

Modul FastQC/MultiQC Yang diperiksa Kapan perlu tindakan? Catatan
Per base sequence quality Kualitas Phred di setiap posisi Pangkas ujung bila kualitas menurun konsisten dan cukup dalam pada banyak read Jangan memangkas hanya karena satu posisi atau satu sampel mendapat peringatan
Per sequence quality scores Kualitas rata-rata setiap read Selidiki bila banyak read berkualitas sangat rendah Tidak selalu berarti seluruh library gagal

Overrepresented sequences Sekuens panjang yang terlalu sering muncul Trim hanya bila sekuensnya cocok dengan adapter/primer yang terverifikasi Dapat juga menunjukkan gen, rRNA, atau artefak biologis berlimpah

Hasil QC awal GSE94345

Pada keenam pasangan FASTQ, kualitas per-basa dan kualitas per-sekuens lulus; GC 44–45% dan median panjang read 76 nt. Tidak ada alasan untuk melakukan quality trimming berbasis Phred pada data ini.

Namun, Overrepresented sequences menemukan pola Illumina/TruSeq pada R1 dan R2 di semua sample, sehingga adapter trimming tetap diperlukan.

Pada agregat laporan, sekuen GATCGGAAGAGCGTCGTGTAGGGAAAGAGTGTAGATCTCGGTGGTCGCCG muncul 459.572 kali (3.18%) dan sekuen GATCGGAAGAGCACACGTCTGAACTCCAGTCACTGACCAATCTCGTATGC muncul 131806 kali (0.91%).

FastQC mengenal pola tersebut sebagai TruSeq adapter dengan indeks. Laporan juga memuat variasi seperti ...TGACCAACCTCG... dan ...TGACCAAACTCG.... Variasi satu basa seperti ini tidak diperlakukan sebagai tiga adapter baru. Melainkan, kemungkinan besar itu adalah mismatch pembacaan pada wilayah adapter.

Pada contoh sekuen GATCGGAAGAGCACACGTCTGAACTCCAGTCACTGACCAATCTCGTATGC, sekuen ini memiliki pola sebagai berikut:

GATCGGAAGAGCACACGTCTGAACTCCAGTCAC  TGACCA   ATCTCGTATGCCGTCTTCTGCTTG
└─────── Adapter Trueseq ───────┘  Index    └─── Adapter Trueseq ───┘

Perhatikan baris kedua pada tabel. Sekuens dengan indeks TGACCA muncul 131.806 kali, dan juga muncul pada variasi sekuen lain. Index TGACCA pada dasarnya merupakan index dari protokol Illumina, yang dapat kita cocokkan pada protol library.

Sebaliknya, sekuens berlebih seperti CTCAAACTTCCATCGGCTTGAAACCGATAGTCCCTCTAAGAAGTGGATAA tidak boleh langsung dimasukkan sebagai adapter hanya karena frekuensinya tinggi.

Sekuens tersebut tidak cocok dengan adapter/primer TruSeq yang terverifikasi dan muncul pada seluruh dua belas FASTQ. Pada RNA-seq, pola demikian dapat berasal dari transkrip biologis yang sangat melimpah. Memangkasnya akan berisiko menghapus sinyal biologis.

Mengapa adapter muncul di read?

Adapter diperlukan saat pembuatan library untuk pengikatan ke flow cell, pengamplifikasian, dan identifikasi sampel (indexing). Bila insert lebih pendek daripada 76 siklus pembacaan, sequencer melewati ujung fragmen cDNA lalu membaca adapter. Jika tidak dihapus, bagian non-biologis ini dapat mengurangi kualitas alignment, menghasilkan soft clipping, dan mengganggu kuantifikasi.

TGACCA adalah indeks dengan 6 basa pada contoh read tersebut. Karena sampel lain dapat memakai indeks lain, kode trimming nantinya tidak boleh hanya menggunakan nilai TGACCA. Sehingga kode trimming haruslah fleksibel menggunakan index 6 basa apapun. Karenaya, kita akan menggunakan N{6}.

Cutadapt mencocokkan template adapter terhadap setiap read, bukan satu per satu baris di tabel Overrepresented sequences. Toleransi mismatch bawaan Cutadapt (--error-rate 0.1) juga memungkinkan kecocokan terhadap variasi kecil yang masih jelas merupakan adapter. Karena itu, cukup gunakan satu template R1 dan satu template R2 yang terverifikasi.

Trimming adapter dengan Cutadapt

Pada GSE94345 ini, tindakan yang didukung laporan adalah penghapusan adapter, bukan pemotongan kualitas secara agresif. --minimum-length 20 membuang pasangan yang setelah adapter dihapus terlalu pendek untuk dipetakan secara bermakna. Cutadapt menjaga pasangan R1/R2 tetap sinkron: bila salah satu mate tidak lolos panjang minimum, pasangan tersebut tidak ditulis.

# bash
DD="$(pwd)/docs/data/rnaseq-gse94345"
samples=(spt23p90_untreated_1 spt23p90_untreated_2 spt23p90_untreated_3 \
  spt23p90_dox_1 spt23p90_dox_2 spt23p90_dox_3)
mkdir -p "$DD/_pipe/trimmed" "$DD/_pipe/cutadapt" \
  "$DD/_pipe/qc_trimmed" "$DD/_pipe/multiqc_trimmed"

for s in "${samples[@]}"; do
  cutadapt --cores 4 --minimum-length 20 \
    -g GATCGGAAGAGCACACGTCTGAACTCCAGTCACN{6}ATCTCGTATGCCGTCTTCTGCTTG \
    -G GATCGGAAGAGCGTCGTGTAGGGAAAGAGTGTAGATCTCGGTGGTCGCCG \
    -o "$DD/_pipe/trimmed/${s}_R1.fastq.gz" \
    -p "$DD/_pipe/trimmed/${s}_R2.fastq.gz" \
    "$DD/raw_reads/${s}_R1.fastq.gz" \
    "$DD/raw_reads/${s}_R2.fastq.gz" \
    > "$DD/_pipe/cutadapt/${s}.log"

  fastqc --threads 4 --outdir "$DD/_pipe/qc_trimmed" \
    "$DD/_pipe/trimmed/${s}_R1.fastq.gz" \
    "$DD/_pipe/trimmed/${s}_R2.fastq.gz"
done

multiqc --force --outdir "$DD/_pipe/multiqc_trimmed" \
  "$DD/_pipe/qc_trimmed" "$DD/_pipe/cutadapt"

Parameter:

  • -g adalah template adapter R1. N{6} menerima indeks enam basa apa pun.
  • -G adalah template adapter R2.
  • -o dan -p menyimpan hasil R1 dan R2 untuk pasangan sampel yang sama.
  • --minimum-length 20 menyaring read/pasangan yang menjadi terlalu pendek setelah adapter dihapus.
  • Berkas cutadapt/*.log merekam jumlah pasangan yang diproses, jumlah yang lolos, dan adapter yang ditemukan; jangan menghapusnya sebelum QC pasca-trimming ditinjau.

QC pasca-trimming dan langkah berikutnya

Buka docs/data/rnaseq-gse94345/_pipe/multiqc_trimmed/multiqc_report.html. Hasil setelah menjalankan perintah di atas adalah sebagai berikut.

Panel Adapter Content kini hanya mencatat kombinasi sampel-adapter di bawah 0,1%, dan kolom Adapter Content pada Status Checks berwarna hijau. Panel lain masih dapat berwarna kuning atau merah, terutama Per base sequence content dan duplikasi.

Semua pasangan mempertahankan sebagian besar read dan seluruh modul Per base sequence quality serta Adapter Content lulus. Peringatan Overrepresented sequences yang tersisa tidak lagi cocok dengan sekuens Illumina/TruSeq, sehingga tidak menjadi alasan untuk trimming tambahan tanpa identifikasi kontaminan yang independen.
